# Judgement calls, and why (September 2026)

Things that could have gone either way, decided so nobody has to re-argue them. Change one by changing this page too.

| Question | Decision | Why |
| --- | --- | --- |
| **HSTS preload** (putting `deskbusiness.co` on browsers' built-in HTTPS-only list) | **Not done.** The `Strict-Transport-Security` header stays at one year with `includeSubDomains`, and Cloudflare redirects http to https. | Preload is close to permanent and requires *every* subdomain, now and in future (including ones that are down like `www.`), to serve valid HTTPS. Getting off the list takes months. The header already protects every browser that has visited once. Revisit when the set of subdomains is settled. |
| **Timestamp columns stored as text** in the older tables | **Leave as they are** (documented in DATABASE.md). | ISO-8601 text sorts and compares correctly; converting is a large migration with no user-visible benefit and some risk. New tables use real timestamps. |
| **A support contact** | The public issue tracker of the desk-api repository (`SUPPORT_URL`, default `https://github.com/mike43stone615/desk-api/issues`), shown on the status page and in the one error message that mentions support. | It needs no mailbox to be set up. Change `SUPPORT_URL` when a support email exists. Anything posted there is public, so people are not asked to post secrets or personal data. |
| **The security contact** (`/.well-known/security.txt`) | Off (404) until an address or page is chosen (`SECURITY_CONTACT`). The good candidate is GitHub's private vulnerability reporting for the repository. | Publishing a contact the operator has not agreed to answer is worse than none. |
| **Branch protection** on `main` | Blocks force-push and deletion only; direct pushes still work. Applied to desk-api (public). The other five repositories are private, and GitHub does not offer this on private repositories without a paid plan. | It stops the two unrecoverable mistakes without slowing a one-person team down with pull-request rules. |
| **Encrypting the off-machine backups** | **Done (20 September 2026).** Public-key encryption: this machine holds only the public key; the private key is kept off the machine (see BACKUP-RESTORE.md). | A key kept on the same machine would be lost with it; with a public key the machine can write backups it cannot read. |
| **DMARC policy** for the sending domain | **Applied 20 September 2026:** `v=DMARC1; p=quarantine; adkim=r; aspf=r; pct=100;` (was `p=none`). Mail that fails both SPF and DKIM alignment is sent to spam. | The mail provider's DKIM is verified and aligned, so legitimate mail passes. Inbound mail is only forwarded by Cloudflare Email Routing and is not affected. No reporting address (`rua`) is set because no mailbox exists for the reports yet. |
| **Bounce and complaint handling** | **Live (20 September 2026).** The provider's webhook (bounces and complaints, to `/webhooks/resend`) is registered, and the service reads the signing secret from the provider with the same API key that sends the mail, so nothing new is stored in the deploy settings. A `RESEND_WEBHOOK_SECRET` setting still overrides it. Tested through Cloudflare 3 times: a signed permanent bounce puts the address on the do-not-mail list, a wrong signature is refused with 401 and stores nothing. | The secret is held by the provider; if it is changed there, the next call asks again. |
| **Terms and privacy pages, acceptance at sign-up** | Drafts only (docs/legal/); nothing published, nothing enforced. | The facts and choices in them are the owner's, and a lawyer should read them first. |
| **Account deletion, password change** | Backend done (`POST /auth/account/delete`, `currentPassword` on `POST /auth/password`); no screen yet. | Screens are a separate piece of work. |
| **Look-alike letters in business names** | Letters from the Cyrillic and Greek alphabets that look like a Latin letter are folded to that letter before names are compared (registry-api `normalize.ts`). | Otherwise a name spelled with a Cyrillic "а" was read as a different word and could be reported available when the real name was taken. Letters with no Latin look-alike are still treated as separators. |
| **compliance-os** | **Retired.** Its data and read API are served by desk-oracle on the same port; no sync, no covering index. | The data was already copied into desk-oracle and the owner wants one home for it. Not carried over: importers, review workflow, scheduled source monitoring. |
| **One response envelope for every endpoint** | **Not done under /v1.** The conventions are written down (API-CONVENTIONS.md) and the small inconsistencies fixed (`invitedByUserId`, 201 + `Location`, one set of rate-limit numbers). A single `{data}` envelope waits for /v2. | It would change every response shape the web and Flutter apps read today. |
| **Per-endpoint key scopes** | **Done as scopes on the Desk API** (`profile`, `drafts`, `businesses`) chosen when a key is created. Desk API keys are read-only by design (only GET routes are on the allowlist). | Lets a developer give a key only the part it needs. Keys stay per API for the two backends. |
| **Soft delete of business members** | **Not done.** Members are removed for real; a restore is a new invitation. Keys stay soft-deleted (revoked) for the audit trail. | A removed person should not remain in the database. |
| **Team or organization keys** | **Built (21 Sep):** separate `teams` table, limits shared across a team, roles owner / admin / developer / viewer (TEAM-KEYS-DESIGN.md). | The owner decided all three open questions. |
| **Score against real outcomes** | **Fixed at the owner's request (21 Sep):** Startup Difficulty now includes the industry's real yearly closure rate (Census BDS), worth 150 of its points, and the category's overall weight rose from 14 to 26. Rank correlation with real exit rates went from -0.04 to -0.73 (same-source caveat in market docs/DATA-QUALITY-CHECKS.md). | The score ignored closure risk; the owner asked for it to rank ideas by risk. |
| **A second live machine / second tunnel connector** | **Not done.** A written cold-standby recipe instead (COLD-STANDBY.md). | A second connector on the same machine adds nothing against a machine failure; a second machine is a cost decision. |
